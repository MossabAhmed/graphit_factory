# نظام محاسبة شركة الشرق الكبرى

موقع ثابت (HTML + JavaScript) بلا خطوة بناء، يعمل على Supabase، ويُنشر مباشرة على Netlify.

## هيكل المجلد

```
index.html              صفحة الدخول للتطبيق، تحمّل الملفات بالترتيب أدناه
styles.css              التنسيقات (Tailwind مُجمَّع + تنسيقات الشركة)
app.js                  واجهة التطبيق (ناتج بناء بأسماء مختصرة، يستدعي وحدات src)
Earthlog.jpeg           الشعار (يجب أن يُنشر بجانب index.html)
src/domain/             الحسابات المالية النقية (بلا واجهة ولا شبكة) — هنا تُكتب أي قاعدة حساب جديدة
  money.js              التقريب، الخصم، التحقق من الأرقام
  projects.js           تكلفة المشروع، الدفعات، الباقي، الفائض، التغاضي، رصيد العميل، السداد العام
  suppliers.js          كشف حساب المورد، توزيع السداد، الفواتير المدفوعة في الشهر
  invoice-number.js     رقم الفاتورة المتسلسل الثابت
src/finance/metrics.js  صفوف التقرير السنوي ومجاميعه
src/reports/annual-report.js  طباعة التقرير السنوي
tests/                  الاختبارات (node بلا أي اعتماديات)
supabase-schema.sql     مخطط قاعدة البيانات (لم يتغير)
netlify.toml            إعداد النشر + إخفاء ملفات غير الموقع
```

ترتيب تحميل السكربتات في `index.html` مهم: `src/domain/*` ثم `metrics.js` ثم `annual-report.js` ثم `app.js`. اختبار `wiring` يتحقق منه.

## تشغيل الاختبارات

```
npm test        # أو: node tests/run-all.js
```

تغطي الاختبارات: الخصم والتقريب، الباقي والفائض والتغاضي، السداد العام للعميل، حساب الموردين وتوزيع السداد، رقم الفاتورة، تطابق التقرير السنوي مع الشهري، سلوك Enter وقفل التمرير، وتشغيل `app.js` فعليًا في بيئة وهمية.

## كيف تضيف ميزة حسابية جديدة

1. اكتب الدالة في `src/domain/` (دالة نقية تأخذ بيانات وترجع نتيجة).
2. أضف لها اختبارًا في `tests/` قبل ربطها بالواجهة.
3. استدعِها في `app.js` عبر `FD.<module>.<function>` (المتغيّر `FD` معرَّف في أول الملف).

لا تكتب منطق الحساب داخل `app.js` ولا تكرره في ملف آخر.

## قواعد الحسابات المعتمدة

- **تكلفة المشروع** = مجموع المكاييل. **الباقي** = التكلفة − المتغاضى عنه − المدفوع.
- لا يظهر المشروع «خالصًا» إلا إذا كان مكتملًا وفيه كيل ولا باقٍ.
- الزيادة المدفوعة **قبل** اكتمال المشروع تبقى «مقدّمًا» داخله. وبعد الاكتمال تصبح رصيدًا للعميل.
- **السداد العام للعميل** (زر في صفحة العميل): وارد بلا مشروع، بتاريخ وملاحظة، يظهر في «المصاريف والواردات» والتقارير، ويُخصم من مستحقات العميل.
- **صافي الحركة النقدية** = الواردات − المصاريف − الفواتير المدفوعة فعلًا (فواتير نقدية + دفعات الموردين).
- **رقم فاتورة المشروع** = `invoiceSerial + 550` بسبع خانات (المشروع الأول 0000551). يُعطى مرة واحدة عند الإنشاء ويُخزَّن داخل بيانات المشروع، وتُرقَّم المشاريع القديمة تلقائيًا مرة واحدة بترتيب تاريخ الإنشاء. لا يتغير بتعديل المشروع.

## ميزات واجهة مهمة

- **السداد العام الموزَّع (صفحة العميل):** تختار مشاريع مكتملة عليها باقٍ، ويُوزَّع المبلغ بترتيب اختيارك: كل مشروع يأخذ باقيه (بعد التغاضي) ثم ينتقل الباقي للتالي. كل جزء يُحفظ دفعةً عادية على مشروعه بتاريخها (داخل المشروع وفي `income`)، والزيادة تُحفظ وارداً عامًا يضاف لرصيد العميل. المنطق في `allocateGeneralPayment` و`buildGeneralPayment` (`src/domain/projects.js`) وكله يُحفظ في عملية واحدة.
- **ألوان الموردين:** `supplierColorMap` (`src/domain/suppliers.js`) يعطي كل مورد لونًا مختلفًا بترتيب أول ظهور له، فلا يتغير لون مورد قديم عند إضافة مورد جديد. 16 لونًا بنسخة للوضع المظلم (`--sup-0..15` في `styles.css`).
- **الظهور التدريجي:** كل قسم (عدا لوحة التحكم التي لها تحريكها) يُغلَّف بـ`div.tab-view`، وCSS فقط (`@keyframes tab-in`) يُظهر العناوين ثم البطاقات والصفوف تباعًا. بلا مؤقتات ولا تأخير حقيقي، ويحترم `prefers-reduced-motion`.

## النشر على Netlify

- الموقع ثابت ولا يحتاج أمر بناء. اترك Build command فارغًا، وPublish directory هو الجذر `.`.
- حجم المشروع نحو 0.5 ميغابايت، ولا يوجد ما يقترب من أي حد للنشر المجاني.
- `netlify.toml` يخفي `supabase-schema.sql` و`tests/` والملفات التوثيقية عن العامة.

## قاعدة البيانات

الكود لا يحتاج أي تغيير في Supabase. الحذف يمحو السجل فعليًا من جدول `app_records` عبر الواجهة البرمجية العادية.
